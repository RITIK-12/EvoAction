EXP-0001 REJECTED parent N000

Hypothesis. The incumbent workflow produces overly short segments (often one frame apart) because the prompt does not discourage fine-grained predictions, leading to poor temporal resolution, low telemetry agreement, and low visual verification. By updating the annotation prompt to explicitly require longer subtasks (minimum ~1.5 seconds) and to avoid predicting a subtask for every sampled frame, the model will produce boundaries that better align with detectable manipulation state changes, improving telemetry agreement and visual verification while keeping inference cost unchanged.

3. Recursive task tree (real dispatch)

Max depth actually reached: 1 (limit 3). Children exist only where an investigator raised an evidence-cited new question that passed the dispatcher's novelty, cycle, depth, fan-out and budget gates. Rejected/deduplicated requests are shown too.

Iteration 1 supervisor: The incumbent workflow frequently over-segments videos, producing boundaries at uniform intervals (e.g., 1‑second steps in galaxea_011) that lack visual confirmation and show poor alignment with gripper telemetry. This leads to low visual_verification and temporal_resolution scores, while telemetry_agreement varies across episodes, indicating that the model struggles to detect true manipulation completion points and instead defaults to a regular segmentation heuristic.

Iteration 2 supervisor: The incumbent workflow produces overly frequent, uniformly spaced segment boundaries (often one per sampled frame). This leads to low visual verification (many boundaries lack a clear manipulation state change) and poor telemetry agreement (many predicted boundaries do not align with gripper open/close events), while duration variability is low due to uniform spacing and temporal resolution suffers because most segments are shorter than two sampled frames.

  • [depth 1] Why does galaxea_011 produce boundaries at 1‑second intervals with zero visual confirmation? done
    Galaxea_011’s 1‑second boundaries result from the workflow’s uniform 1 Hz sampling (one frame per second) combined with the model predicting a subtask for each sampled frame; because each predicted segment is shorter than two frames, the model cannot rely on visual change between frames, yielding zero visual verification.
    implication: Increase the sampling rate (e.g., to 2 Hz or higher) or modify the annotation prompt to encourage longer segments, so that boundaries can be anchored to visually detectable changes and visual verification improves.
    tools run: episode_predictions, inspect_frames, sampling_coverage, self_assessment · cites: SELF-0ce68ee9fe, EV-fd5d685402, EV-a8a57be878, EV-a89faebf8c · model: nvidia/NVIDIA-Nemotron-3-Super-120B-A12B
  • [depth 1] Why do galaxea_007 and robointer_droid_000012 have low telemetry agreement despite moderate visual verification? done
    Galaxea_007 and robointer_droid_000012 show zero telemetry agreement because their gripper events (telemetry hints) occur far from the predicted segment boundaries, yielding zero precision/recall, while visual verification remains moderate because some visual confirmation exists but is not perfectly aligned.
    implication: Refine segment boundaries using telemetry hints (e.g., align predicted boundaries to gripper open/close events) or increase sampling rate to better capture telemetry changes, thereby improving telemetry agreement.
    tools run: episode_predictions, self_assessment, telemetry_hints · cites: SELF-0ce68ee9fe, EV-8003cb5f5f, EV-92f796e446 · model: nvidia/NVIDIA-Nemotron-3-Super-120B-A12B
  • [depth 1] Why does the incumbent predict a boundary every second in galaxea_011, and do those boundaries correspond to actual manipulation state changes? done
    The incumbent predicts a boundary every second because the workflow samples at 1 Hz and the annotation model treats each sampled second as a distinct segment (see EV-9b5b91ca09’s 1‑second predicted segments). These boundaries do not precisely align with actual manipulation state changes; telemetry hints show gripper events occurring near but not exactly at integer seconds (EV-b0fc9c361d), and visual inspection confirms a change at ~5 s (EV-dc7b55db92) while many second‑marked boundaries lack any telemetry or visual evidence of change (SELF-4e3d54401c shows visual_verification = 0.0 and only 10 gripper events across 30 predicted boundaries).
    implication: Lower the fixed 1 Hz sampling or enable adaptive segmentation based on telemetry/visual change detection, and adjust the prompt to allow variable-length segments rather than forcing a new subtask each second.
    tools run: episode_predictions, inspect_frames, self_assessment, telemetry_hints · cites: SELF-4e3d54401c, EV-9b5b91ca09, EV-b0fc9c361d, EV-dc7b55db92 · model: nvidia/NVIDIA-Nemotron-3-Super-120B-A12B
  • [depth 1] In robointer_droid_000012, why does the predicted boundary at 10.0 sec have high visual verification but zero telemetry agreement? done
    In robointer_droid_000012 the predicted boundary at 10.0 sec is visually verified (visual_verification = 1.0) because the vision model detects a clear manipulation state change around that time, but there is no telemetry signal (gripper state change) near 10.0 sec; the nearest gripper hints are at 5.0 sec (distance 5.0) and 8.1 sec (distance 1.9), yielding zero telemetry agreement.
    implication: Consider relaxing the telemetry‑agreement criterion (e.g., increase distance tolerance or incorporate additional signals like end‑effector pause) so that boundaries supported strongly by visual evidence but lacking proximate gripper events are not penalized.
    tools run: episode_predictions, inspect_frames, self_assessment, telemetry_hints · cites: SELF-4e3d54401c, EV-6f36b2f5a4 · model: nvidia/NVIDIA-Nemotron-3-Super-120B-A12B

Limitations

  • 3 held-out episodes: a feasibility result, not statistically established generalization.
  • Temporal Segment F1 evaluates boundaries only; it does not assess the semantic correctness of subtask labels.
  • The outer-boundary-snapped score is an evaluator-only variant; WGO-Bench's official scorer was not available to verify.
  • Costs are provider-reported tokens x listed per-token prices from /v1/models; billing was not reconciled.
